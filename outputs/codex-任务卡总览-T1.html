TASK-001 / T1 · W1 · draft

候选配置与免费数据接入

原始任务卡 ↗

建立可配置的固定与动态候选范围，取得真实免费数据，并向后续计算提供带来源、时点和口径的资料。

依赖：无前置实现任务；数据源账号及免费接口条件需在设计和接入时核实。

覆盖 F02、F03；F11 的数据环境部分后续采用完整技术方案

验收标准

本阶段确认这些交付标准；当前没有实现、测试或验收结果。

  1. AC01 · 正常

    配置能表达默认候选、动态前 10 规则及用户自定义对象；生成的候选清单可追溯到配置或当日累计成交额规则。

  2. AC02 · 正常

    形成真实可调用的数据获取能力，能取回可得候选的行情和供后续指标使用的历史数据；仅有接口说明或一份缺口清单不能代替核心取数实现。

  3. AC03 · 正常

    数据覆盖记录列全 A1 第 3.4 节的数据组，区分实际取得、条件未满足和尝试后仍不可得，并给出来源与时间。

  4. AC04 · 边界

    候选去重、无效对象和全市场统计资格均明确处理；无法取得前 10 所需资料时显示缺口，不用固定关注项凑成前 10。

  5. AC05 · 边界

    行业排名、市场统计与官方指数序列各自的口径可辨认；数据源不满足排除规则时不标为已满足。

  6. AC06 · 异常

    认证、网络、额度或字段缺失有明确状态；替代源保留自身来源与口径；旧值不能被重新标记为本轮实时值。

  7. AC07 · 权限与交接

    凭据不出现在配置示例、HTML 或提交文件；后续任务可以获取同一轮数据与缺口信息；未打通核心真实取数时按实际阻塞交付。

要做范围与不做边界

要做

  • 提供配置文件入口，支持行业板块、宽基指数、个股和由用户指定的实际交易品种映射；校验对象名称与数据源代码。
  • 默认候选为当日累计成交金额前 10 的行业板块，加煤炭、银行、电力、工业金属，以及上证 50、沪深 300、中证 500、中证 1000、中证 2000、创业板、创业板 50、科创板 50；重复对象合并并保留来源理由。
  • 通过免费 API 或兼容 MCP 获取候选行情与历史、全市场和行业资料、融资与 ETF 份额、跨市场观察等所需数据；逐项记录可得性及剩余缺口。
  • 建立供全市场统计使用的基础证券集合，落实北交所和 ST 排除条件；行业成交额口径不能落实时记录限制，不静默替代。
  • 完成候选生成所需的确定性过滤、去重和行业成交额排序；为 TASK-003 提供盘面统计需要的基础数据和口径。
  • 保存数据来源、源日期/时间、获取时间、单位/币种、分类与必要的复权信息；标明历史、当前值及估算性质。
  • 首选来源失败或缺字段时查找其他真实免费来源补充，并记录尝试结果；确实无法取得时说明缺口及影响。

不做

  • 不开发技术指标、Codex 推导、交易计划、完整 HTML 操作页与周期调度。
  • 不购买付费行情，不申请或使用交易权限，不代选用户未指定的 ETF/个股作为交易品种。
  • 不把网页抓取作为唯一数据保障，不以填充值或虚构行情补齐来源缺口。
产物、交接与待核实事实

产物：配置入口与示例、真实数据获取能力、规范化结果及覆盖/缺口记录；实现文件落在 src/，说明与证据落在本项目 records/ 或 outputs/ 的 Codex 文件。

交接：向 TASK-003、TASK-004 提供对象清单、行情/市场资料与缺口信息；具体契约在本卡技术设计中确定。

事实核实安排
数据源账号、免费字段和来源服务条件决定真实数据可得范围；设计时核对，必要的用户登录在具体接入步骤办理。
行业分类、ST 标记、宏观与“中证金融/微盘股”对应序列由 Codex 核对公开定义及代码，无法确认时列出对象歧义。
当前 Mac 与后续 Windows 的接口运行前置不能将仅支持某客户端的能力默认写成双平台已可用。

涉及外部 API/MCP、新依赖和跨平台数据获取，采用独立完整方案。 本卡获签后才开始对应技术设计。

TASK-002 / T1 · W2 · draft

交易知识档案与确认记录

原始任务卡 ↗

为逻辑、技术、模式提供可持续维护的档案，区分待确认与已确认内容，并保留历史引用。

依赖：无前置实现任务；对象引用方式与 TASK-001 的设计对齐。资料整理可在数据权限待落实时进行。

覆盖 F06；D3 中知识档案的本地保存与迁移后续采用完整技术方案

验收标准

本阶段确认这些交付标准；当前没有实现、测试或验收结果。

  1. AC01 · 正常

    逻辑、技术、模式都有可保存、读取和修订的条目，能收纳当前原话及后续补充。

  2. AC02 · 正常

    新归纳条目可作为待确认内容保存，只有明确的用户确认才进入已确认集合。

  3. AC03 · 边界

    同一概念能够跨层引用；草稿、已确认内容及历史版本可区分，来源不被丢失。

  4. AC04 · 边界

    已生成报告/计划所引用的版本仍可读取；修改当前条目不改变其历史依据。

  5. AC05 · 异常

    无效、损坏或引用缺失的档案被明确提示，不能静默转为已确认内容或让关联信息失真。

  6. AC06 · 持久与交接

    重启后档案可继续使用，迁移文件保留版本和来源；TASK-004/005 可读取已确认版本及其引用信息。

要做范围与不做边界

要做

  • 保存逻辑、技术和模式条目，容纳定义、适用对象、依据/案例及必要参数说明；允许自然语言与可结构化条件共同归档。
  • 录入用户已明确的原话与已知事实，保留原始来源；系统新归纳的具体定义或规则作为草稿，待翔宇确认。
  • 支持创建、查阅、修订和用户确认；确认人与确认对象可追溯。
  • 保留条目版本，后续修订不改写已被报告和计划引用的历史版本。
  • 超跌反弹等概念可按交易出发点与市场状态分别引用，不强制只属于一个层面。
  • 档案在本地持久保存，文件可以迁移；为 TASK-006 的整体资料迁移提供所需档案内容。

不做

  • 不批量建立全量研报库，不训练预测模型，不替用户确认新交易规则或编造历史胜率。
  • 不开发完整页面、交易计划和自动多设备同步；知识工作流中的 Codex 调用由 TASK-004 提供。
产物、交接与待核实事实

产物：本地档案能力、初始原话档案、版本与确认记录、供后续读取的调用方式；技术格式在设计阶段确定。

交接：向 TASK-003 提供适用的已确认技术规则，向 TASK-004/005 提供逻辑/技术/模式档案和版本引用；迁移整合由 TASK-006 完成。

事实核实安排
初始具体规则与证据用户已给出的原话可入档；未提供的阈值、具体定义或案例保持待补充。
资料迁移与引用一致性在设计中明确格式、版本兼容和冲突处理；首期不自动跨机同步。

涉及多类档案、持久化、用户确认和跨任务历史引用，按完整方案处理。 本卡获签后才开始对应技术设计。

TASK-003 / T1 · W3 · draft

技术指标与全市场盘面计算

原始任务卡 ↗

把真实行情转为可复算的日/周技术结果与全市场结构事实，为 Codex 解读提供一致依据。

依赖：TASK-001 的真实数据和对象/口径资料；TASK-002 中适用的已确认定义。依赖可用性按实际产物核对。

覆盖 F04、F05后续采用完整技术方案

验收标准

本阶段确认这些交付标准；当前没有实现、测试或验收结果。

  1. AC01 · 正常

    已明确的均线、OBV、MACD、CCI 均有确定的计算口径与参数记录，使用同轮可追溯数据，结果可按记录复算。

  2. AC02 · 正常

    日线为主、周线辅助的结果可区分；历史长度、复权与成交量单位足以判断当前计算是否有效。

  3. AC03 · 正常

    盘面结果覆盖已要求的数据类别，可得项实际产生结果，缺失项显示原因与受影响内容。

  4. AC04 · 边界

    全市场统计没有被候选清单替代；无法落实全市场范围/排除规则的数据明确标注口径缺口。

  5. AC05 · 边界

    未收盘 K 线、休市数据、日频外部序列与当前行情分别标明时间性质，不能因本轮刷新而伪装成新发布值。

  6. AC06 · 异常

    缺历史、单位冲突、无效数值或源不完整时，对相关指标/结论返回明确的不足状态，不用无依据数字填满结果。

  7. AC07 · 交接

    TASK-004/006 可读取同一轮技术事实、市场变化、公式参数和缺口，单轮结果不被后续数据覆盖。

要做范围与不做边界

要做

  • 计算候选对象的日线技术指标，以周线辅助观察；保留指标公式/参数和价格、成交量的来源口径。
  • 处理足够历史、复权、缺口及未完成日/周 K 线，输出形成中或证据不足状态。
  • 形成全市场涨跌家数、成交量/额、涨跌停/封板、行业涨跌及资金方向等事实，统计范围落实剔除北交所与 ST。
  • 整理融资余额、ETF 份额和跨市场序列的变化、源日期与单位；仅在口径允许且数据足够时计算比较。
  • 复用 TASK-001 的行业当日累计成交额排名和候选生成结果，避免另设一套相互冲突的前 10 规则。
  • 输出供后续展示与推导使用的事实和变化，保留可回溯的数据轮次、公式版本和缺口。

不做

  • 不负责行情账号接入、知识确认、Codex 模式解释、计划生成或交易执行。
  • 不引入未批准的策略阈值，不把指标组合分数当成已验证胜率，不运行全历史策略回测。
产物、交接与待核实事实

产物：技术计算与盘面事实能力、公式/参数说明、按轮次保存的结果及不足状态；实现不触碰 tests/。

交接：向 TASK-004 交付事实及变化，向 TASK-006 交付图表数据；指标事实和 AI 判断保持可辨认。

事实核实安排
指标公式、复权、周线聚合与参数Codex 在设计中按可核实口径说明，不要求翔宇代选实现库。
资金流、封板率和行业汇总的来源定义依赖 TASK-001 的字段覆盖记录；缺依据时保留不可判定。

涉及多项指标、时间与复权口径、跨来源统计及潜在新依赖，采用完整方案。 本卡获签后才开始对应技术设计。

TASK-004 / T1 · W4 · draft

Codex 推导与候选解释

原始任务卡 ↗

让已有 Codex 按已确认档案应用四层体系，解释限定候选的机会、冲突和等待理由，并保留当时依据。

依赖：TASK-001 的数据与候选、TASK-002 的知识版本、TASK-003 的技术/市场事实；目标运行机的 Codex 登录与调用能力。

覆盖 F07后续采用完整技术方案

验收标准

本阶段确认这些交付标准；当前没有实现、测试或验收结果。

  1. AC01 · 正常

    在可用 Codex 环境中完成真实推导调用，输出能关联当轮候选、程序事实和已确认知识版本。

  2. AC02 · 正常

    候选结论包含可追溯的主要依据及反证/缺口，能够输出等待或观察，不要求每轮必有推荐。

  3. AC03 · 边界

    结果遵守限定候选和 D1；用户未指定的交易品种不被系统自行替换或选定。

  4. AC04 · 边界

    规则未确认、证据不足或三层分歧按 D2 呈现；系统新归纳的知识不能在本轮自动升级成用户已确认规则。

  5. AC05 · 异常

    登录、额度、调用失败、超时或输出不符合约定时有明确失败/降级状态；保留程序结果及原始输出，不把旧报告当成本轮新解读。

  6. AC06 · 交接

    推导结果、输入快照和引用可供 TASK-005/006 使用；不同运行的原始记录可区分并回看。

要做范围与不做边界

要做

  • 组织一次推导所需的候选、全市场背景、跨市场资料、技术结果、知识版本和数据缺口。
  • 通过目标设备上可用的 Codex 使用方式执行受控推导，保存输入、输出、运行状态和引用关系。
  • 围绕熟悉逻辑、技术状态与市场模式解释候选，提供支持证据、反证、冲突和等待/观察结论。
  • 遵守配置指定的候选范围和用户指定交易品种映射；仅有板块/指数时保留方向级结论。
  • 关键证据不足或规则未确认时说明限制，允许模式多侧面并存，不填造概率或强制选出机会。
  • 为 TASK-005 提供可复用的 Codex 调用与分析引用能力，使计划/复盘复用同一事实体系。

不做

  • 不代替程序重新编造数值，不把模型语气或置信度当胜率，不自主扩展交易品种。
  • 不替用户确认知识或计划，不执行交易，不将付费模型 API 作为未经确认的默认替代渠道。
  • 不承担知识库持久化、完整计划业务状态或最终页面实现；由对应任务负责。
产物、交接与待核实事实

产物：Codex 调用与当轮解释能力、输入/输出和引用记录、可区分的失败状态；具体调用和 Skill 组织方式留技术设计。

交接：向 TASK-005 提供有依据的方向结论与可复用推导能力，向 TASK-006 提供摘要、详情和状态。

事实核实安排
Codex 在 Mac/Windows 的实际可用调用方式、登录与额度在设计与实现自检时核实；当前会员事实不代表所有设备已登录。
推导输出格式、引用方式与失败边界由本任务技术设计明确，供 TASK-005/006 复用。

涉及外部 Codex 进程/工具调用、登录环境和跨任务输出约定，采用完整方案。 本卡获签后才开始对应技术设计。

TASK-005 / T1 · W5 · draft

交易计划、执行回填与复盘

原始任务卡 ↗

把分析结果连接到经用户确认的计划、实际执行记录和复盘，并将经验作为待确认修订反馈到交易档案。

依赖：TASK-002 的知识版本与持久记录、TASK-004 的推导能力；相关数据轮次来自 TASK-001/003。A1 D1–D3 已确认。

覆盖 F08、F09后续采用完整技术方案

验收标准

本阶段确认这些交付标准；当前没有实现、测试或验收结果。

  1. AC01 · 正常

    系统可以拟定包含已确认字段的计划草稿，用户也可直接记录，并能完成明确确认、查看和后续记录。

  2. AC02 · 正常

    确认对象和版本明确，计划关联生成时的分析与知识依据；新一轮刷新不覆盖旧计划。

  3. AC03 · 边界

    未指定实际品种时保留方向级计划，关键字段缺依据时显示待补充；不擅自挑选替代 ETF 或生成无依据数值。

  4. AC04 · 正常

    用户回填与计划关联；计划外记录、执行偏差和未提供的信息可区分，系统只依据实际填写内容判断。

  5. AC05 · 边界

    计划修改保留历史，复盘引用原计划与原始执行信息，能够表达原因未明或证据不足。

  6. AC06 · 确认与交接

    复盘修订保持待确认，只有翔宇确认才纳入 TASK-002 的已确认知识；本地记录可持久读取并随整体资料迁移。

  7. AC07 · 异常

    输入无效、关联缺失、存储失败或 Codex 复盘失败时，已有确认内容和执行原文得到保留，失败原因可见。

要做范围与不做边界

要做

  • 根据分析生成计划草稿，字段为标的、逻辑/技术/模式依据、买入条件、退出条件、仓位与风险限制、有效期；支持用户直接记录计划。
  • 由翔宇明确确认计划，并保留该版本的内容、时间与分析/知识引用；后续刷新只产生提示或修订草稿。
  • 遵守 D1：实际 ETF/个股由用户指定；未指定时仅形成方向级观察计划，标明待补充执行品种。
  • 遵守 D2：缺少关键数据、规则或个人限制时，计划保留待补充内容，不填无依据仓位、价格或风险数值。
  • 接受翔宇回填的执行信息，关联已有计划或标记计划外记录；保留原始说明和可核对的时间、动作等内容，具体字段在设计中明确。
  • 据已回填内容检查计划偏差并辅助复盘，区分当时判断、计划规则、实际执行和结果；不足以定位原因时明确说明。
  • 复盘形成的逻辑/技术/模式修改作为待确认内容交 TASK-002，确认后再纳入；本地保存并支持整体资料迁移。

不做

  • 不连接券商成交系统，不自动买卖，不声称能够阻止用户在外部交易软件操作。
  • 不把填写记录等同于已确认计划，不自动改写原计划或已确认知识，不从单次盈亏直接认定策略因果。
  • 不训练模型、不做全历史回测，不承担多机自动同步或最终界面布局。
产物、交接与待核实事实

产物：计划草稿/确认/修订能力、人工执行记录、偏差与复盘记录、知识修订回流；完整交互页面由 TASK-006 承接。

交接：向 TASK-006 提供计划、确认、回填、复盘操作及状态；向 TASK-002 交付待确认知识修订。

原始任务卡 ↗

把已完成能力整合为可在联网 Mac/Windows PC 使用的本地交易辅助系统，提供按钮、运行时每小时刷新和简洁 HTML 图表。

依赖：TASK-001～TASK-005 的可用产物和约定；目标运行环境。引用依赖的实际版本，不能以未完成前置默认可用。

验收标准

本阶段确认这些交付标准；当前没有实现、测试或验收结果。

  1. AC01 · 正常

    用户可以在目标电脑启动本地系统，通过页面按钮触发一次完整取数、计算、Codex 解读和结果呈现；运行前置有明确说明。

  2. AC02 · 正常

    系统运行期间具备每 1 小时刷新能力，手动/周期状态可辨认，触发重叠不会相互覆盖原始轮次与确认记录。

  3. AC03 · 展示

    首页具有市场摘要、候选、计划提醒和图表，主要信息清晰；完整指标与依据可展开，数据/分析时间和缺口可见。

  4. AC04 · 业务操作

    知识确认、计划确认/手工记录、执行回填和复盘可通过界面完成，引用与人工确认结果保留。

  5. AC05 · 边界

    退出服务、休眠、休市或断网时，状态与实际可用性一致；恢复后取得最新可用数据，不集中补跑大量旧分析。

  6. AC06 · 异常

    数据源或 Codex 失败时保留最近成功结果和本轮错误，旧结果不能伪装成当前轮；无效配置、存储问题可定位。

  7. AC07 · 迁移与环境

    本地资料可在声明支持的 Mac/Windows 环境迁移并维持引用；平台实际自检及未验证项如实记录，最终双平台覆盖由小步正式验证，不凭声明视为通过。

  8. AC08 · 交付边界

    运行界面实际调用前序能力；导出的自包含 HTML 无外部 CDN 依赖，凭据不进入页面/提交，系统不具备下单权限。

要做范围与不做边界

要做

  • 提供本地运行入口及浏览器操作页，把配置、数据、计算、Codex 推导、计划和复盘接为完整流程。
  • 实现手动触发按钮，以及系统运行期间每 1 小时刷新；显示周期状态、当前进度与最近成功/失败轮次。
  • 让手动与周期触发采用一致流程，处理触发重叠、服务停止、休眠和断网后的恢复状态。
  • 首页突出市场判断及时间、少量候选及主要理由、计划提醒和关键图表；完整列表、指标、反证与缺口按需展开。
  • 提供知识确认、计划确认/直接记录、执行回填及复盘的对应操作，保留每步业务确认含义。
  • 提供某轮结果的自包含 HTML 查看能力；运行界面与静态报告的能力范围清楚，源数据时间和分析时间分别呈现。
  • 支持本地档案持久使用及 Mac/Windows 之间的文件迁移，整体资料包含知识、计划、执行和关联历史；首期不自动同步。

不做

  • 不增加自动交易、付费行情、未经同意的模型 API、多机云端同步或手机专用应用。
  • 不在服务退出后承诺后台刷新，不把断网期间的旧数据标为新数据。
  • 不重写前序指标/归档/计划规则，不把静态 HTML 示意页当成可运行的系统。
