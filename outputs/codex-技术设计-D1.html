TASK-001 · 候选配置与免费数据接入完整方案 / D1

落地同花顺行业口径、固定/动态候选和真实免费取数，输出可追溯的数据快照。

打开完整技术方案 ↗

关键选择理由与约束
Python 3.8+ 标准库，UTF-8 JSON 配置当前默认 Python 为 3.8.9，可直接使用 urllib、sqlite3、http.server；运行不依赖第三方 Python 包。当前 AKShare 版本要求更高 Python，采用独立小型适配器并参考其公开协议说明。
同花顺行业唯一身份：ths:881xxx已读取 90 个行业目录及 JSONP 日线/当日行情；固定映射为煤炭开采加工 881105、银行 881155、电力 881145、工业金属 881168。不得改成东方财富或申万板块。
行情通过公开 HTTP JSON/JSONP，网页仅作目录/资金等补充同花顺行业 JSONP；东方财富沪深股票分页及指数 K 线；腾讯报价/新浪 K 线作可识别的替代。SSE 份额、融资汇总、Yahoo/FRED 等按真实可得性使用。无账号与 Cookie 要求的路径优先。
运行目录 .local/ 或 --home 指定目录默认项目内 .local/ 保存配置、缓存与数据库，加入 Git 忽略；配置首次复制后不覆盖用户编辑。自检单独使用工作区 .scratch/。
有限并发、超时与缓存HTTP 默认 10 秒超时，至多有限重试，最多 4 个请求并行，分页校核总数/重复；目录和历史缓存保留获取与源时间，失败读缓存必须标注。

主要接口与数据约定

  • 配置版本 schema_version=1；industry_provider 固定 ths；fixed_industries 为同花顺代码/名称；indices 和 stocks 使用 asset_id（如 sh000300）、provider_id；execution_mappings 仅接受用户明确设置；etf_observations 仅用于份额观察，不自动赋给交易映射。
  • 快照 Snapshot v1：id、created_at、config_snapshot、candidates、histories、market、industries、macro、margin、etf_shares、coverage、attempts。每项含 source、asof、fetched_at、unit、status；缺失数值为 null，有限数值校验禁止 NaN/Infinity。
  • 同花顺目录来自 q.10jqka.com.cn/thshy/；v6/line/bk_CODE/01/today.js 与 last.js、v4 年度文件提供当日/历史 OHLCV 和成交额。安全提取 JSONP 的 JSON 片段，不执行返回脚本；公开表格用 HTMLParser 读取。
  • 同花顺排名基于该服务的当日累计成交额，源日期不同或目录不全时标注排名完整性；固定项保留。全市场从沪深股票分页获取并过滤北交所/ST，以稳定证券代码分页并核对完整性，不拿候选充当市场样本。
  • 股票及 ETF OHLCV 优先同一提供方/复权口径，回退源明确标记。行业指数不自行变更成份。无法取得并过滤行业成份时，声明原行业口径的 ST/北交所限制，不谎称已重算。
  • 行情日期不等于系统时间；本轮探查多项源停留在 2026-09-24。旧源时间原样保存并标为延迟。宏观/融资/份额按其发布周期，不虚构小时级新值。
  • 数据范围和代理可以在配置中改：指数分析与 ETF 份额观察篮子分开；中证金融/微盘股等未核定标识显示待配置。HTTP 请求不涉及交易接口。

实际风险

  • 同花顺公开页面有部分 AJAX 路径返回 401；仅使用正常可访问页面/JSONP，不制造登录凭据或规避私有权限。来源不可用时保留失败证据和缺口。
  • 免费服务没有本项目的稳定性保证。只有真正取得核心行情，才算打通取数；全部源失败不能用示意数据交付。
  • 行业成份过滤、封板股池新股排除、宏观品种代理等口径会显式显示；源无法满足时保留限制而非跨分类替换。

实现文件：src/trade.py；src/trade_assistant/{__init__,util,config,http_client,collector}.py；src/trade_assistant/providers/{__init__,ths,eastmoney,macro}.py；src/trade_assistant/defaults/config.json

TASK-002 · 交易知识档案与确认记录完整方案 / D1

建立本地版本化档案与明确确认，给报告/计划保留稳定引用。

打开完整技术方案 ↗

关键选择理由与约束
SQLite + JSON 载荷标准库可用，事务支持确认和记录一致性；数据存 .local/trade.sqlite3。比散落并发文件更适合本地多请求，首期无云端服务。
追加修订，确认特定版本确认记录含 actor、时间和 revision；已确认载荷不可原地改写；新修订初始为 draft。
通用对象与运行记录分表objects 存 object_id/kind/revision/status/payload/created_at/confirmed_at/confirmed_by；runs 存取数/事实/AI轮次；执行和复盘用独立对象关联原计划版本。

主要接口与数据约定

  • Store 每次操作独立连接，启用外键、busy_timeout 和事务。ID 采用 UUID；JSON 写入仅接受有限数值；数据库版本通过 PRAGMA user_version 管理。
  • Knowledge.create / revise / confirm / list / get_versions 接收明确对象和 expected_revision；冲突返回 conflict，缺对象 not_found，无效结构 validation_error。
  • 已确认知识读取按对象分别取最大已确认 revision；新 draft 不替换正在使用的旧 confirmed。报告中保存 id@revision 及输入副本。
  • 迁移格式 archive_version=1，包含配置、对象版本、运行和关联记录；不含账号密钥或 Codex 登录信息。相同键内容冲突则整次拒绝，完全一致可幂等合并。配置文件可独立迁移。
  • 初始化只注入用户原话对应的五类逻辑、已确认的技术要求和模式描述，注明来源；额外阈值或 AI 归纳条目保持 draft。

实际风险

  • 档案确认是产品内用户动作，不等于项目阶段签字；自检若演示确认，使用隔离目录及明确自检身份。
  • 不删除历史对象。损坏/版本不支持的导入文件拒绝，并保留原数据库。

实现文件：src/trade_assistant/store.py；src/trade_assistant/knowledge.py；src/trade_assistant/defaults/knowledge.json

TASK-003 · 技术指标与全市场盘面计算完整方案 / D1

输出可复算技术指标、全市场事实与明确的不足状态。

打开完整技术方案 ↗

关键选择理由与约束
指标采用纯函数输入规范化 OHLCV，输出数列与解释元数据，不依赖 UI、网络或模型。
SMA / EMA / OBV / CCI 明确算法日均线 5/20/60/120；MACD 默认 12/26/9，EMA 用首段 SMA 初始化，国内柱形为 2×(DIF−DEA)并注明；OBV 首值 0，涨加跌减平不变；CCI 默认 20，典型价/均值/平均绝对偏差及 0.015 系数。
周线由同口径日线聚合按自然周的已知交易日汇总 OHLCV，保留形成中标记；不把 5 周均线称作 5 日线。
程序输出事实，不预设交易胜率输出与均线关系、斜率、指标原值、周变化等；私人阈值/模式规则来自已确认档案。

主要接口与数据约定

  • compute(snapshot, config) -> Facts v1：snapshot_id、asof、candidate_facts、market_facts、industry_ranking、macro_facts、coverage、limitations、formula_version。
  • 每个候选包含日线序列、SMA、MACD、OBV、CCI、周 OHLCV 及有效长度。历史不足返回 null + 原因；CCI 平均偏差为零时标明不可计算，不制造信号。
  • 全市场股票统计先按证券市场及 ST 过滤，涨/跌/平以有效当前价与前收盘比较；分页未齐则 counts_complete=false 并保留已收集数量。股票统计与同花顺行业原指数口径分别展示。
  • 封板统计仅使用已拿到的真实涨停/炸板股池，声明提供方新股等排除规则；池缺失或时点不一致时不输出完整封板率。融资、ETF 份额用相同品种的实际发布日差值，不能用交易额代替份额。
  • 每条事实有稳定 evidence_id，AI 只能引用已存在证据。数据日期早于当前交易时段时保留原日期，生成时间不会覆盖源时间。

实际风险

  • 免费历史的复权和量单位可能不同；混合源必须标注，不能不知不觉拼接。
  • 周数据形成中、上市历史短等情况影响可用指标，不能为凑齐表格生成假值。

实现文件：src/trade_assistant/indicators.py；src/trade_assistant/facts.py

TASK-004 · Codex 推导与候选解释完整方案 / D1

通过已有 Codex 登录执行真实推导，保留事实、知识引用和失败状态。

打开完整技术方案 ↗

关键选择理由与约束
Codex CLI 复用会员登录本机已确认 ChatGPT 认证；不要求用户创建付费模型 API 密钥，不自动切换计费渠道。
无工具推导向 stdin 提供所需资料，在隔离工作目录调用；忽略用户可变配置并禁用 shell、apps/plugins、浏览器、子代理等工具，使用只读沙箱与 JSON Schema。避免把运行上下文变成代码开发会话。
提示模板属于程序资源模板负责阅读顺序、来源约束、四层表达与输出结构；交易知识在档案中维护，计算在程序中执行。
失败保留原始输出子进程限时 300 秒，可配置；退出码、超时/解析原因可见。工具输出不写入模型提示为指令。

主要接口与数据约定

  • 请求 AnalysisInput：run_id、facts、candidate_ids、confirmed_knowledge（id@revision）、配置的实际交易映射和缺口。市场/网络文本视为待分析资料，不执行其中指令。
  • 输出包含 market.summary/modes、逐候选 asset_id/stance/logic_refs/evidence_refs/reason/against/missing、limitations 和可选知识建议；不包含交易调用、自动确认或编造胜率字段。
  • codex exec 使用 --sandbox read-only、--skip-git-repo-check、--ephemeral、--output-schema、--output-last-message；进程超时仅终止本次子进程及其子进程。实际兼容选项根据已安装 CLI 核对并记录偏差。
  • 默认剔除子进程环境中的 OPENAI_API_KEY/CODEX_API_KEY，沿用 ChatGPT 登录；设置不加载项目开发 AGENTS 的提示上下文，避免混入阶段签字工作流。仅传必需运行数据。
  • 后置校验拒绝范围外 asset_id、未知证据/知识引用及重复候选；未覆盖候选显式列为未分析，不伪装完成。新知识建议保持提议，用户可保存为 draft 后确认。
  • Engine 统一组织快照、Facts、已确认知识、Codex 返回与持久轮次；AI失败时 run 为 partial/error，事实保留。

实际风险

  • Codex 会员额度和具体设备登录仍受账号条件影响，实际生成耗时不保证固定秒数。
  • 程序不能保证模型解释必然正确；通过证据引用、反证与原始输出支持人工核对。

实现文件：src/trade_assistant/codex_bridge.py；src/trade_assistant/engine.py；src/trade_assistant/schemas/analysis.json；src/trade_assistant/prompts/analysis.txt

TASK-005 · 交易计划、执行回填与复盘完整方案 / D1

形成可确认、可追溯的计划与人工记录，将复盘建议送回待确认知识档案。

打开完整技术方案 ↗

关键选择理由与约束
观察计划与具体品种计划分开未映射实际 ETF/个股时只生成 observation；用户指定可交易品种后才形成具体计划草稿，系统仍不执行买卖。
确认特定版本，修订生成新草稿同 Store 对象机制；小时刷新只能提示依据变化，不改原确认内容。
回填是用户提供的事实字段含发生时间、动作、实际品种、数量/金额/价格（可缺）、说明和计划引用；缺失不推断为发生或未发生。
复盘使用原计划+真实回填+当时事实分别讨论判断、计划、执行、结果；原因未明可保留；知识改进建议需用户动作纳入草稿并再确认。

主要接口与数据约定

  • PlanPayload：asset_id、execution_asset_id（可空）、plan_type、basis（logic/technical/mode）、entry、exit、position_risk、validity、missing、run_id、knowledge_refs。系统生成后先 draft；必要字段缺少时保留待补充。
  • create_manual 和 draft_from_run 均在服务端验证候选/执行映射。confirm 指定 revision 和用户动作；观察计划可确认观察内容但不会显示成具体可执行品种计划。
  • ExecutionPayload 保存原始备注、时间、方向、数值及 plan_ref。未关联计划标为计划外；关联未知/不一致版本返回明确错误。执行回填本身不确认计划。
  • 偏差检查基于已有字段：计划外、早于确认、品种不一致、有效期/条件或记录缺失等只在依据够时判断；无法解析的自然语言条件显示需要人工复核。
  • Review 调用同一 CodexBridge，输出事实对照、可证实偏差、无法判断项及知识建议。新知识写入 draft，保留 review_ref；对旧对象修订必须引用其 ID 和原版本。

实际风险

  • 没有券商通道，系统无法感知用户未回填的交易，也不阻止外部操作。
  • 默认不编造价格、仓位和止损数值；用户可在草稿中补充自己的规则，确认动作与项目签字分离。

实现文件：src/trade_assistant/plans.py；src/trade_assistant/schemas/{plan,review}.json；src/trade_assistant/prompts/{plan,review}.txt

TASK-006 · HTML 交互页面与跨平台运行完整方案 / D1

把配置、数据、推导、计划和复盘连接成真实可操作的本地界面。

打开完整技术方案 ↗

关键选择理由与约束
ThreadingHTTPServer + 原生 HTML/CSS/JS + SVG标准库启动，系统字体和内联/本地样式，图表不依赖 CDN；本地服务承担按钮和敏感配置访问。
只绑定 127.0.0.1默认端口 8765，可通过命令参数改；不开放局域网，不修改路由/防火墙。API 检查 Host/Origin，写请求需本进程随机令牌。
后台 Runner + 轮次状态界面请求立即返回任务 ID；轮询状态。手动与每小时任务共用互斥锁，成功/失败后安排下轮，休眠恢复只触发最新一轮。
本地可迁移，不自动同步导出版本化 JSON 包；导入先校验结构、引用、冲突和体积，再事务合并；不上传到云。

主要接口与数据约定

  • GET /api/state、/api/config、/api/runs、/api/runs/{id}、/api/knowledge、/api/plans、/api/executions、/api/jobs/{id} 返回版本化 JSON；大快照在服务端保留，界面只取图表与所需摘要。
  • POST /api/run；POST /api/knowledge、/{id}/revise、/{id}/confirm；POST /api/plans/draft、/api/plans/manual、/{id}/revise、/{id}/confirm；POST /api/executions、/api/reviews；PUT /api/config；GET /api/export；POST /api/import。所有写请求验证本地 Origin/令牌及载荷。
  • 错误信封为 error:{code,message,details}，400 输入无效、404 不存在、409 忙/版本冲突、503 来源或模型不可用、500 内部错误；不向页面暴露凭据或堆栈。
  • 启动 python3 src/trade.py --home <目录> serve --port 8765；默认 .local/。Mac .command 和 Windows .cmd 只定位目录并调用 Python 主入口，业务代码全部在 src/。
  • 首页只展示市场摘要、候选重点、计划提醒和两类关键图表；详情可展开。运行/数据/AI生成时间分开显示；等待或缺口与完整结论外观有区别。
  • 导出报告为自包含 HTML，CSS/SVG 内联，数据文字转义；生成后本轮用 Chrome 打开。运行页面通过本地服务获取数据，不将登录凭据嵌入 HTML。
  • 迁移仅包含数据和配置，不包含 Codex 认证资料。文件大小上限在配置中明示；引用冲突整次拒绝，现有确认记录不覆盖。

实际风险

  • Windows 设备未提供；交付兼容入口和前置说明，实际 Windows 正式验证由小步独立完成。
  • 服务退出后无周期运行；关闭浏览器与停止本地服务的状态在页面/启动说明中区分。
