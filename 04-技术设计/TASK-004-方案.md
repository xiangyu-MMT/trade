## 接口、数据与错误约定

1. 请求 AnalysisInput：run_id、facts、candidate_ids、confirmed_knowledge（id@revision）、配置的实际交易映射和缺口。市场/网络文本视为待分析资料，不执行其中指令。

2. 输出包含 market.summary/modes、逐候选 asset_id/stance/logic_refs/evidence_refs/reason/against/missing、limitations 和可选知识建议；不包含交易调用、自动确认或编造胜率字段。

3. codex exec 使用 --sandbox read-only、--skip-git-repo-check、--ephemeral、--output-schema、--output-last-message；进程超时仅终止本次子进程及其子进程。实际兼容选项根据已安装 CLI 核对并记录偏差。

4. 默认剔除子进程环境中的 OPENAI_API_KEY/CODEX_API_KEY，沿用 ChatGPT 登录；设置不加载项目开发 AGENTS 的提示上下文，避免混入阶段签字工作流。仅传必需运行数据。

5. 后置校验拒绝范围外 asset_id、未知证据/知识引用及重复候选；未覆盖候选显式列为未分析，不伪装完成。新知识建议保持提议，用户可保存为 draft 后确认。

6. Engine 统一组织快照、Facts、已确认知识、Codex 返回与持久轮次；AI失败时 run 为 partial/error，事实保留。

跨任务共用约定：不可变 run_id 与 object_id@revision；所有源时间与生成时间分开；知识/计划确认由明确用户动作完成；数据缺口可追溯。后续若协议实质变化，在受影响方案和实现记录中说明，不无声更换。
