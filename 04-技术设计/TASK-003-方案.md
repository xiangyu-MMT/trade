## 目标与边界

输出可复算技术指标、全市场事实与明确的不足状态。

| 任务卡验收标准 | 方案响应 |
|---|---|
| AC01、AC02 | 纯 Python 指标计算，固定并记录公式/参数、历史长度、单位和源；日线主、周线辅助。 |
| AC03、AC04、AC07 | 从 Snapshot 计算全市场涨跌/量能和行业变化，保留覆盖范围；输出 Facts v1 供 AI/图表。 |
| AC05、AC06 | 形成中 K 线与日频序列明确标注，缺历史、零分母或不完整市场不得返回伪完整值。 |

本方案沿用已签 T1 的要做/不做范围与 A1 的 D1–D3 决定：人工指定实际品种、依据不足保留观察/等待、本地文件可迁移；没有自动交易、付费行情或多机云同步。

## 方案与选择依据

| 关键选择 | 理由及处理 |
|---|---|
| 指标采用纯函数 | 输入规范化 OHLCV，输出数列与解释元数据，不依赖 UI、网络或模型。 |
| SMA / EMA / OBV / CCI 明确算法 | 日均线 5/20/60/120；MACD 默认 12/26/9，EMA 用首段 SMA 初始化，国内柱形为 2×(DIF−DEA)并注明；OBV 首值 0，涨加跌减平不变；CCI 默认 20，典型价/均值/平均绝对偏差及 0.015 系数。 |
| 周线由同口径日线聚合 | 按自然周的已知交易日汇总 OHLCV，保留形成中标记；不把 5 周均线称作 5 日线。 |
| 程序输出事实，不预设交易胜率 | 输出与均线关系、斜率、指标原值、周变化等；私人阈值/模式规则来自已确认档案。 |

实现文件：src/trade_assistant/indicators.py；src/trade_assistant/facts.py

## 接口、数据与错误约定

1. compute(snapshot, config) -> Facts v1：snapshot_id、asof、candidate_facts、market_facts、industry_ranking、macro_facts、coverage、limitations、formula_version。

2. 每个候选包含日线序列、SMA、MACD、OBV、CCI、周 OHLCV 及有效长度。历史不足返回 null + 原因；CCI 平均偏差为零时标明不可计算，不制造信号。

3. 全市场股票统计先按证券市场及 ST 过滤，涨/跌/平以有效当前价与前收盘比较；分页未齐则 counts_complete=false 并保留已收集数量。股票统计与同花顺行业原指数口径分别展示。

4. 封板统计仅使用已拿到的真实涨停/炸板股池，声明提供方新股等排除规则；池缺失或时点不一致时不输出完整封板率。融资、ETF 份额用相同品种的实际发布日差值，不能用交易额代替份额。

5. 每条事实有稳定 evidence_id，AI 只能引用已存在证据。数据日期早于当前交易时段时保留原日期，生成时间不会覆盖源时间。

跨任务共用约定：不可变 run_id 与 object_id@revision；所有源时间与生成时间分开；知识/计划确认由明确用户动作完成；数据缺口可追溯。后续若协议实质变化，在受影响方案和实现记录中说明，不无声更换。

## 风险与处理

- 免费历史的复权和量单位可能不同；混合源必须标注，不能不知不觉拼接。
- 周数据形成中、上市历史短等情况影响可用指标，不能为凑齐表格生成假值。
