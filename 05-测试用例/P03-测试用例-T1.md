## 0. 本文件的组织方式与理由

实现已经从 I1 迭代到 I5，同一份代码被多张任务卡先后覆盖（例如均线同时涉及 TASK-003 的计算、TASK-006 的页面、TASK-009 的显示配置）。若严格按 `TASK-XXX-测试用例.md` 一卡一档，同一条行为要写三遍，且容易出现两份文档结论不一致。

因此本文件**按测试域组织成 11 组**，在每条用例的「来源」列标注它覆盖的 REQ/TASK；第 12 节给出 TASK → 用例的反查覆盖表。测试执行记录与验收结论写在 TASK 的测试区（待翔宇许可后回填，见第 13 节说明）。

## 2. 测试策略

| 层 | 手段 | 可否自动 | 说明 |
|---|---|---|---|
| L1 单元/离线 | 直接用 Python 调用被测模块，构造夹具 | 可，全部自动 | 覆盖校验、计算、排序、存储、生命周期 |
| L2 接口集成 | 用 `--port 0` 起真实本机服务，用 http.client 调用真实路由 | 可，全部自动 | 覆盖鉴权、状态码、错误信封、归档 |
| L3 真实数据/AI | 用已保存真实快照重放；按需真实调用 Codex | 部分 | 依赖网络与会员服务，失败保留原始记录 |
| L4 浏览器交互 | Chrome 人工/半自动 | 否 | 勾选、刷新保持等交互由人工确认，报告中单列 |

**隔离要求**：所有自动化用例在 `tests/` 下自建临时数据目录，不读写项目 `.local/`，不触碰 `.scratch/` 既有证据，不修改 `src/`。
